# 🍳 Recipe Manager

A fullstack web application to **create, browse, edit and delete cooking recipes**.
It is made of a REST API (Node.js / Express / TypeScript) and a React client, and it was built as my end-of-piscine web project at Epitech.

---

## ✨ Features

- 📖 **Browse** all recipes as cards (name, difficulty, preparation time)
- 🔍 **View** a recipe in detail: ingredients list and step-by-step instructions
- ➕ **Add** a new recipe with a dynamic ingredients list
- ✏️ **Edit** an existing recipe (the form is pre-filled with the current data)
- 🗑️ **Delete** a recipe, with a confirmation prompt
- ✅ **Server-side validation** of every request body, with clear HTTP status codes

## 🧰 Tech stack

| Part | Technologies |
| --- | --- |
| **API** | Node.js, Express 5, TypeScript, `ts-node`, `cors`, `dotenv` |
| **Client** | React 19, React Router, TypeScript, Vite |
| **Storage** | A local JSON file (`api/recipes.json`) read and written with `fs/promises` |
| **Icons** | [Framework7 Icons](https://framework7.io/icons/) (loaded from a CDN) |

## 🚀 Getting started

### Prerequisites

- [Node.js](https://nodejs.org/) 20 or later
- npm (installed with Node.js)

### 1. Clone the repository

```bash
git clone git@github.com:Ibanphlp/Recipe-Manager.git
cd Recipe-Manager
```

### 2. Install the dependencies

```bash
# API
cd api
npm install

# Client
cd ../client/my-react-app
npm install
```

### 3. Configure the API (optional)

The API reads its port from `api/.env`. The default is `3000`:

```env
PORT=3000
```

> ⚠️ The client currently calls the API at `http://localhost:3000`. If you change the port, update the URL in the client.

### 4. Run the project

Open **two terminals**.

**Terminal 1 — API** (http://localhost:3000)

```bash
cd api
npm start
```

**Terminal 2 — Client** (http://localhost:5173 by default)

```bash
cd client/my-react-app
npm run dev
```

Then open the URL printed by Vite in your browser.

## 🔌 API reference

Base URL: `http://localhost:3000`

| Method | Endpoint | Description | Success | Errors |
| --- | --- | --- | --- | --- |
| `GET` | `/recipes` | List all recipes | `200` + array of recipes | — |
| `GET` | `/recipes/:id` | Get one recipe | `200` + recipe | `404` |
| `POST` | `/recipes` | Create a recipe | `201` + created recipe | `400`, `500` |
| `PUT` | `/recipes/:id` | Update a recipe | `200` + updated recipe | `400`, `404` |
| `DELETE` | `/recipes/:id` | Delete a recipe | `204` (no body) | `404` |

### Recipe model

```ts
interface Recipe {
  id: number;                              // generated by the API (highest id + 1)
  name: string;                            
  preparationTime: number;                 // in minutes, >= 0
  difficulty: "easy" | "medium" | "hard";
  ingredients: string[];
  instructions: string;
}
```

### Example

```bash
curl -X POST http://localhost:3000/recipes \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Omelette au fromage",
    "preparationTime": 10,
    "difficulty": "easy",
    "ingredients": ["3 œufs", "50 g de fromage râpé", "10 g de beurre"],
    "instructions": "1. Battre les œufs. 2. Cuire à la poêle. 3. Ajouter le fromage et plier."
  }'
```

An invalid body returns:

```json
{ "error": "Invalid recipe body" }
```

## 🧠 How it works

- The **client** is a single-page app with four routes: `/` (list), `/details/:id`, `/add` and `/modify/:id`. It talks to the API with `fetch`.
- The **API** is split in two layers: `index.ts` handles HTTP concerns (routes, validation, status codes) and `store.ts` handles data access (reading and writing `recipes.json`).
- New recipe ids are computed from the **highest existing id + 1**, so ids stay unique even after deletions.
